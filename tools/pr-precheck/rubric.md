# Rubric: is this pull request ready to submit?

Grade the PR, not the polish. Every check reads one artifact against another: the diff against the plan, the description against the diff, the evidence against the plan's test plan, the PR against the repo's stated asks. A terse PR that does exactly what its plan says, proves it, and meets the template is ready. A polished one that quietly does more, proves the wrong path, or ignores a stated ask is not. An honest shortfall (less than the whole plan, recorded in the plan's deviation notes and stated in the description) is judged as scoped, not as a failure.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The diff's changed files and hunks, read against the plan's in-scope / out-of-scope statements, its approach, and its deviation notes (see evidence guide: Plan fidelity) | Pass if every hunk in the diff implements something the plan or a deviation note names, AND every change the plan commits to is in the diff or is named as deferred in a deviation note or the description. Fail if the diff contains a change the plan neither names nor records as a deviation (a new option or flag, a rewrite, a rename pass, an edit to a file the plan never touches, rewording unrelated text), especially one the plan scopes out; or if a planned change is missing with no note anywhere. | required |
| description-matches-diff | Each factual claim in the PR title and description (what changed, "implements the plan exactly", "no changes beyond…", "docs now document…"), each matched against the diff (see evidence guide: Plan fidelity) | Pass if every change the description says the PR makes is in the diff, every fidelity claim holds, and any deferral the plan records is stated in the description too. Judge substance, not wording: a loose summary of a change that is in the diff ("one function touched" when the fix also adds a small helper it calls, a test list that names cases the added test covers) is not a false claim. Fail if the description claims a change the diff doesn't contain (a docs update, a test, a second fix), claims fidelity ("exactly as planned", "no functional changes outside…") that an unplanned hunk contradicts, or omits a deferral the plan records. | required |
| decisive-evidence | The test evidence's before/after, read against the plan's test plan and the issue's reproduction trigger (see evidence guide: Test evidence) | Pass if, for every failure mode the issue's reproduction shows (each reported broken behavior and its trigger), the evidence re-runs that trigger (or a regression test built from it) and shows the failing output before and the fixed result after. The before must quote the actual failure (the error text, the wrong value, the wrong output). The after may be pasted output, or the observed result stated against the same command ("no error", "file not listed") when the before quotes the failure. When the plan applies one fix to sibling code paths the issue's repro doesn't exercise separately (the same change in three parallel methods), re-running the issue's trigger covers them. Test-plan items that check something that wasn't broken (a control, "a successful save still clears", a new warning or edge behavior) are not failure modes: a test in the diff, a stated result, or silence about them never fails this check. Fail if the evidence for a failure mode is a statement with no command and no quoted before ("tested locally", "works on my machine", "tests pass"); if it exercises only a control or an unchanged path (the case that never broke, a different method or code path than the issue's trigger); or if the issue or plan names several distinct failure modes (different triggers or different broken behaviors) and the evidence re-runs some and is silent on the rest. | required |
| clean-diff | The unified diff and the commit list (see evidence guide: Diff quality) | Pass if every hunk serves the change: no debug output, no commented-out code or earlier attempts, no dead or unused functions, no hunk of import reordering or whitespace / re-indent churn in code the fix doesn't touch, no hunk that removes and re-adds identical lines without changing anything. Unchanged lines shown as removed and re-added inside a hunk that also makes the planned change (for example, the arguments around an edited call) are diff noise, not debris. Fail if any debris hunk or debris line is present, however correct the actual fix is. | required |
| standards-honored | The repo-facts block's PR template and contribution asks and stated AI policy (live: `.github/PULL_REQUEST_TEMPLATE.md`, `docs/CONTRIBUTING.md`, any AI_POLICY.md / AGENTS.md), and the thread's maintainer comments, read against the description and diff (see evidence guide: Standards and comms) | Pass if every ask the repo states for a PR is met or explicitly explained in the description: each required template section has real content, a required issue link (e.g. `Closes #N`) is present, required checklist items and required artifacts (a changelog/whatsnew entry, removing a seeded bug's marker) are present in the diff, ticked boxes are backed by evidence, an AI-use disclosure is present where the policy requires one, and any maintainer direction in the thread is engaged. If the repo states no template and no policy, grade pass. Fail if any stated ask is visibly ignored. | required |
| repo-checks-shown | The test evidence's output for the repo's own checks or suite (live: `make test-unit`, `make test-integration`, `make lint`, `make typecheck`) (see evidence guide: Test evidence) | Pass if the repo's own checks were run and their outcome is pasted (a failing or "no tests ran" result reported honestly with its reason counts). | preferred |

## Verdict rule

- accept only if every `required` check passes.
- `unclear` on a `required` check counts as fail: evidence you cannot see in the package is a claim you cannot verify.
- `standards-honored` is graded pass, never unclear, when the repo states no PR template and no policy.
- `preferred` checks are reported but never change the verdict.
- Otherwise reject.
